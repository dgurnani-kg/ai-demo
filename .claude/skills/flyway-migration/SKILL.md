# Adding a migration

Migrations live in `src/main/resources/db/migration`. Flyway applies them in order at
startup, and `spring.jpa.hibernate.ddl-auto=validate` then checks that the JPA mappings
agree with the result. A mismatch fails application startup — which means it fails every
`@SpringBootTest`, loudly, before anyone reviews the diff.

## The rule that matters

**Never edit a migration that has been applied.** Flyway records a checksum; changing an
applied file makes the application refuse to start with a checksum mismatch, and on a
shared database it breaks everyone. Add `V{n+1}__description.sql` instead. A hook in this
repo blocks edits to existing migrations, so if you find yourself trying, stop and add a
new one.

## Naming

`V{n}__snake_case_description.sql` — two underscores, sequential `n`, no gaps.
Check the highest existing number first:

```bash
ls src/main/resources/db/migration
```

Descriptions say what the migration does to the schema: `V4__create_reservation.sql`,
`V5__add_book_shelf_location.sql`. Not `V4__changes.sql`.

## Conventions in this repo

- Table and column names are `snake_case`, singular table names: `book`, `loan`,
  `library_member`. (`member` is reserved on some engines — don't use it.)
- Primary keys: `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
- Timestamps: `TIMESTAMP WITH TIME ZONE`, mapped to `java.time.Instant`.
- Foreign keys are always named: `CONSTRAINT fk_{table}_{target} FOREIGN KEY ...`.
- Index anything a repository method filters on, and name it `idx_{table}_{purpose}`.
- Seed data goes in its own migration, never mixed with DDL.

## The JPA side

A new table needs the entity to match or startup fails:

- `@Table(name = "snake_case")`, `@Column(name = "snake_case")` on anything not identical.
- A `protected` no-arg constructor for JPA, and a real constructor for the rest of us.
- Getters only — no setters. State changes go through named methods (`loan.returnOn(now)`).
- Repositories extend `JpaRepository` and live in `..domain..`.

## Verify

```bash
./gradlew test --tests '*BookEndpointTest'
```

Any `@SpringBootTest` will do — if the migration and the mapping disagree, the context
fails to load and you will see it immediately.
